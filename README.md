# ITPU VR — «По ту сторону кода»

Интерактивный VR-проект для **Meta Quest 3**, рассчитанный на 8–10 минут университетского показа. Посетитель последовательно исправляет интерфейс, ожидание гостя и проверку доступа, наблюдая результат своих действий в виртуальной части кампуса.

## Текущий статус

Последняя подтверждённая локальная точка разработки — **21 сентября 2026 года**.

- Реализованы доменные правила C01/C02/C03, сброс сеанса и защита от устаревших событий.
- Unity-проект использует один XR Origin, collision-aware locomotion, движение левым стиком, snap turn, взаимодействие контроллерами и руками.
- Для актуального локального кандидата EditMode прошёл 16/16, PlayMode — 36/36.
- Android development build `0.5.1-visual-refinement` (code 38) был успешно собран и прошёл проверку OpenXR/manifest/signature.
- Установка code 38 и повторная визуальная проверка в Quest не завершены: устройство не определялось по USB в момент последнего checkpoint.
- Стабильные 90 Гц, thermal/soak и release candidate пока не подтверждены.

Этот GitHub-репозиторий содержит только проверенную публичную часть исходников. Он не содержит APK, лиц, голосов, внутренних планов, локальных отчётов, Blender/FBX-ассетов и полной Unity-сцены. Поэтому публичный clone не является готовой демонстрационной сборкой.

## Игровой цикл

1. **C01 — событие и обработчик.** Кнопка существует, но маршрут появляется только после подключения настоящего обработчика.
2. **C02 — ожидание гостя.** Поведение гида меняется после добавления правила `WaitForGuest`.
3. **C03 — авторизация до операции.** Отказ не меняет данные; корректные ALLOW/DENY/ALLOW проверяются наблюдаемым результатом.
4. Финал должен использовать проверенную конфигурацию текущего сеанса, а не заранее записанный успех.

Свободные взаимодействия — кофе, доска, бумага и безопасное восстановление предметов — развиваются отдельно и не должны блокировать основной сценарий.


## Локальные проверки

Для независимой доменной части:

```powershell
dotnet run --project src/domain-tests/ITPU.Domain.Tests.csproj
node tests_v7/test_auto_acceptance.cjs
```

Полные Unity EditMode/PlayMode проверки и Android build требуют локальной сцены и ассетов, которые намеренно не публикуются. Открывать проект следует через Unity Hub точной версией `6000.6.2f1` с Android Build Support.

## Управление

- левый стик — плавное перемещение;
- правый стик — snap turn 30° по умолчанию;
- grip — захват;
- trigger — выбор/активация;
- телепортация — comfort fallback;
- руки — pointing/pinch и визуальный указатель, когда tracking доступен.

После pause/focus/tracking loss движение требует neutral rearm. Потеря tracking руки не считается броском удерживаемого предмета.

## Архитектура

Проект сохраняет границы `domain → adapters → presentation → data`:

- domain хранит правила и состояние задач;
- adapters связывают их с Unity/OpenXR/input;
- presentation показывает фактическое domain-состояние;
- data содержит конфигурацию, локализацию и стабильные идентификаторы.

UI не вычисляет собственную «победу», сброс детерминирован, а callbacks прошлого сеанса не должны изменять новый.
